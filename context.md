# Context — Kahani Build Session

Chronological record of what was implemented across this build session.

## 1. Starting Point (Audit)

User had cloned `https://github.com/jui1ee/Bidirectional-Indian-Sign-Language-Translator.git` into `/home/juilee/projects/Kahani/`. Two halves:

- **Text-to-ISL**: rule-based NLP with googletrans, no reordering, broken `/translate` endpoint, ISL grammar logic in `code.py` + `isl_nlp.py`. Backend on FastAPI. Frontend `Web-UI/` empty.
- **ISL-to-Text**: webcam + MediaPipe + 2 small TFLite classifiers, broken sentence-assembler, Flask MJPEG stream.

Original 1219-word `words.txt` was generated by scanning a non-existent `static/signfiles/` folder. No avatar renderer existed.

## 2. User Brief (the rebuild spec)

A kid-friendly web app: parent/teacher uploads a story (`.txt`/`.pdf`/`.docx`), child plays it back with three things in sync:

1. Story text with current word highlighted
2. ISL sign video for that word
3. Audio narration (browser TTS)

Decisions the user specified and I followed:

- **Delete ISL→Text** entirely (webcam not in scope).
- **Drop ISL grammar reordering** — word order preserved so video + text highlight always reference the same word.
- **Drop multilingual translation** (googletrans unreliable) — TODO comment left.
- **Fix concurrency bug** — tokenize must be pure, no module state.
- **Replace words.txt + SiGML/avatar** with real video dictionary from **INCLUDE** dataset (Zenodo 4010759, CC-BY-4.0).
- **Build React (Vite)** frontend from scratch (no EJS).
- **Add file upload + parsing** to FastAPI.
- **Sync mechanism**: `SpeechSynthesisUtterance.onboundary` drives text + video + fingerspell simultaneously.
- **Kid-friendly UI**: pastel palette, rounded shapes, mascot, large tap targets, simple actions.

Out of scope: gesture recognition, multilingual input, auth, cloud, mobile.

### 3.3 Backend (`backend/main.py`)

- Pydantic `StoryToken` model with `{display_word, lemma, sign_video, is_fingerspelling}`.
- `get_nlp()` lru-cached spaCy loader.
- `get_sign_dict()` lru-cached dictionary loader.
- `tokenize()` — pure function: tokenize + lemmatize only (parser/tagger/NER disabled). Safe under concurrency.
- File parsers: `_extract_text_from_txt` (utf-8 → latin-1 fallback), `_extract_text_from_pdf` (pypdf), `_extract_text_from_docx` (python-docx).
- Endpoints:
  - `POST /api/upload` (multipart, 5 MB limit, .txt/.pdf/.docx)
  - `POST /api/tokenize` (JSON body)
  - `GET /api/signs/{lemma}` (single lookup)
  - `GET /healthz` (liveness probe)
  - `GET /static/signs/...` (mounted via `StaticFiles`)

### 3.4 Frontend (`frontend/src/App.jsx`)

- Three screens: `UploadScreen`, `PreviewScreen`, `PlaybackScreen`.
- Mascot SVG (inline, no asset deps) — happy + thinking moods.
- `SpeechSynthesisUtterance.onboundary` → binary-search charIndex → token index.
- One event drives text highlight, video swap, and fingerspell letter chip.
- Play/Pause/Restart + Slow (0.8×) / Normal (1.0×) speed toggle.
- Pastel palette: pink #FFD6E7, sky #C7E9FF, mint #C9F7E1, yellow #FFF4C2, lavender #E2D6FF.
- Rounded Fredoka headings + Quicksand body via Google Fonts.

## 4. Later Additions (recent work)

This section documents the changes made in the subsequent work pass on top of the initial build described above.

### 4.1 Hemg dataset for real fingerspelling clips

`backend/signs/build_fingerspelling_clips_from_hemg.py`:

- Downloads a single ~292 MB Parquet shard from `Hemg/Indian_sign_language_dataset` on HuggingFace.
- Reads the shard with `pyarrow`; iterates 42,745 rows picking one representative image per class.
- 35 classes total: 9 digits (`1`–`9`, label index `0..8`) and 26 letters (`A`–`Z`, label index `9..34`). No class for digit 0.
- Letterbox-pads each image into a 320×320 square on a soft pastel background, encodes as a 320×320 / 0.6 s h264 single-frame looped MP4 using `imageio[ffmpeg]` + numpy.
- Writes `backend/static/signs/_letters/a.mp4 … z.mp4` (replacing the placeholders) and `backend/static/signs/_digits/1.mp4 … 9.mp4` (new folder).

### 4.2 Frontend: per-char routing by kind

`frontend/src/App.jsx` (`PlaybackScreen`):

- The `[activeIdx, tokens]` effect builds the chip row from the active token's characters, classifying each as `letter` or `digit`.
- `currentVideoSrc` routes to `/static/signs/_letters/<c>.mp4` or `/static/signs/_digits/<c>.mp4` based on the chip's kind.
- `frontend/src/App.css` adds `.letter-chip.digit` styling in pastel cyan so digit chips are visually distinct from yellow letter chips.

### 4.3 Per-unit utterance scheduler

The PlaybackScreen no longer relies on `onboundary` for cadence. It builds a `spokenUnits` array (one entry per spoken unit — a single letter/digit for fingerspell tokens, the whole word for sign-video tokens) and a `spokenSegments` lookup. The new scheduler:

- `speakUnit(idx)` creates a `SpeechSynthesisUtterance(unit.surface)` for each unit.
- `onstart` sets `(activeIdx, activeLetter)` atomically.
- `setTimeout(UNIT_DURATION_MS = 1350)` advances to the next unit when the timer fires.
- A `[currentVideoSrc]` effect updates `<video>` src and calls `.load() + .play()` whenever the active unit's video path changes.
- After the last unit, a `setTimeout(POST_ROLL_MS = 700)` schedules a delayed reset to the upload screen so the final word / letter stays visible briefly.

The scheduler and `onstart` are the only audio-driven paths. No reliance on `onend` or `<video>.onEnded>` for advance — these had proven unreliable across browsers and caused stuck-state issues with repeated same-clip units.

### 4.4 Existing dictionary + clips

- `backend/signs/dictionary.json` retains its 22 entries from the partial INCLUDE download (animal, horse, mouse, we, they, you (plural), good evening, good night, thank you, pleased, morning, afternoon, evening, night, time, second, summer, spring, winter, fall, monsoon, season).
- `backend/static/signs/<lemma>.mp4` serves each lemma at the path returned by the dictionary.
- `backend/signs/ATTRIBUTION.md` and the app footer credit both INCLUDE and Hemg.

### 4.5 Frontend cosmetics

- Default playback speed bumped from 1.0× to **0.8×** as a kid-friendly default; the existing Slow / Normal toggle stays so users can still pick 1.0×.
- `<video>` element got `preload="auto"` so the browser fetches metadata immediately on element creation.

## 6. Documented Gaps

- **Dictionary is sparse** (~22 INCLUDE entries), so many children's-story words fall back to fingerspelling — by design.
- **Hemg has no class for digit 0** — stories containing `0` will 404 on that clip.
- **Safari TTS** fires `onstart` / `onend` less reliably; on Safari the per-letter advance may collapse but each unit still gets its full 1.35 s of stage time.
- **Long INCLUDE clips** (~11 MB, 1920×1080) take ~100–500 ms to decode the first frame, so the user may see only the first ~700–1100 ms of a 2.16 s clip — acceptable for kid-friendly read-along.
- **Backend lru_cache invalidation**: `get_sign_dict()` caches the first read of `signs/dictionary.json`. Restart the backend after rebuilding the dictionary.

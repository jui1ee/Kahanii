# Context — Kahani Build Session

Chronological record of what was done, what changed, what went wrong, and what is currently functional.

## 1. Starting Point (Audit)

User had cloned `https://github.com/jui1ee/Bidirectional-Indian-Sign-Language-Translator.git` into `/home/juilee/projects/Kahani/`. Two halves:

- **Text-to-ISL**: rule-based NLP with googletrans, no reordering, broken /translate endpoint, ISL grammar logic in `code.py` + `isl_nlp.py`. Backend on FastAPI. Frontend `Web-UI/` empty.
- **ISL-to-Text**: webcam + MediaPipe + 2 small TFLite classifiers (~1k params each), broken sentence-assembler (`if np.unique(predictions[-10:])[0] == hand_sign_text:` never fires — author commented the bug themselves), Flask MJPEG stream.

Original 1219-word `words.txt` was generated by scanning a non-existent `static/signfiles/` folder for SiGML/avatar files. No avatar renderer existed.

## 2. User Brief (the rebuild spec)

A kid-friendly web app: parent/teacher uploads a story (`.txt`/`.pdf`/`.docx`), child plays it back with three things in sync:

1. Story text with current word highlighted
2. ISL sign video for that word
3. Audio narration (browser TTS)

Decisions the user specified and I followed:

- **Delete ISL→Text** entirely (webcam not in scope)
- **Drop ISL grammar reordering** — word order preserved so video + text highlight always reference the same word
- **Drop multilingual translation** (googletrans unreliable) — TODO comment left
- **Fix concurrency bug** — tokenize must be pure, no module state
- **Replace words.txt + SiGML/avatar** with real video dictionary from **INCLUDE** dataset (Zenodo 4010759, CC-BY-4.0)
- **Build React (Vite)** frontend from scratch (no EJS)
- **Add file upload + parsing** to FastAPI (didn't exist)
- **Sync mechanism**: `SpeechSynthesisUtterance.onboundary` drives text + video + fingerspell simultaneously
- **Kid-friendly UI**: pastel palette, rounded shapes, mascot, large tap targets, simple actions

Out of scope: gesture recognition, multilingual input, auth, cloud, mobile.

## 4. Bugs Encountered + Fixed

### 4.1 The `pipe` ternary (minor)
`main.py:149-150` had convoluted logic computing `pipe = nlp.get_pipe("lemmatizer") if ... else None` then deciding which `nlp()` call to make — both branches did the same thing. Flagged for cleanup, not critical.

### 4.2 Backend endpoint `/translate` (pre-existing)
The `/translate` endpoint passed the Pydantic class `InputText` instead of the string. Not fixed (out of scope — googletrans dropped).

### 4.3 Build script "cached" check (CRITICAL)
```python
# Before
if dest.exists():
    print(f"  ✓ cached: {dest.name}")
    return
```
Treated partial downloads as complete. Then crashed at extract step.
```python
# After
if dest.exists() and (expected_size is None or dest.stat().st_size >= expected_size):
    print(f"  ✓ cached: {dest.name}")
    return
# Truncate stale partials so curl starts fresh
if dest.exists():
    dest.unlink()
```
Also wrapped `extract()` in try/except `BadZipFile` so partials are skipped gracefully.

### 4.4 INCLUDE files are .MOV, not .mp4 (CRITICAL)
Filter `endswith(".mp4")` dropped 90%+ of clips.
```python
suffix = Path(filename).suffix.lower().lstrip(".")
if suffix not in {"mp4", "mov"}:
    return None
```
Also fixed `rglob("*.mp4")` to scan `*` then filter inline.

### 4.5 Lemmas were "mvi 0017" garbage (CRITICAL)
Used filename stem only. INCLUDE names clips `MVI_4565.MOV`. Real label is in parent directory: `Seasons/61. Summer/MVI_4565.MOV` → lemma `summer`.
```python
def label_from_path(path):
    parent = path.parent.name
    parent_lemma = _extract_lemma_word(parent) if parent else None
    if parent_lemma and parent.lower() not in CATEGORY_NAMES:
        return parent_lemma
    return _extract_lemma_word(path.name)
```

### 4.6 Path("61. Summer").stem = "61" (CRITICAL)
`Path` splits on last `.`, eating " Summer". Fixed with custom extension detection:
```python
suffix = Path(text).suffix
if (suffix and len(suffix) <= 6 and " " not in suffix
        and suffix.lstrip(".")[:1].isalpha()):
    text = Path(text).stem
# Strip "61. " prefix and "Ex. " prefix with regex
text = re.sub(r"^\s*\d+\.\s*", "", text)
text = re.sub(r"^\s*[A-Za-z]+\.\s*", "", text)
```

### 4.7 Backend lru_cache stale after dictionary rebuild (operational)
`get_sign_dict()` is lru-cached at backend startup. After rebuilding `signs/dictionary.json`, the running process still returns the empty dict. Fix: restart backend. Documented as expected behavior.

### 4.8 Marker file prevents re-extraction (operational)
`extract()` writes `.__include_extracted__` even when the zip was incomplete at extract time. After the zip completes, the marker says "already done" and re-extract is skipped — but data is incomplete.
Fix: `find .cache/include/raw/ -name ".__include_extracted__" -delete` then re-run extract.
Better long-term fix needed: only write marker after extraction succeeds AND zip size matches expected.

## 5. The INCLUDE Download Saga (what went wrong)

### Timeline
1. First attempt: 12 zips in parallel. Connection drops after ~30 minutes. 5GB downloaded, 0/12 complete. Killed all curl.
2. Second attempt: 6 zips (smart subset, smallest of each pair). Started ~30 min in. Some files hit 90% then dropped.
3. `_download_small.sh` exited after 4 retries × 5 files = 20 failed attempts.
4. Restarted with `_resume_parallel.sh` (10 retries each, parallel). All 5 non-Colours files completed. Colours_1of2 hit 10 retries.
5. Colours_1of2 attempted 10 retries in resume script — gave up at 67MB out of 1.2GB.

### What actually got downloaded
| File | Size | Status |
|---|---|---|
| Animals_2of2.zip | 1020 MB | ✓ complete, valid |
| Days_and_Time_3of3.zip | 813 MB | ✓ complete, valid |
| Greetings_2of2.zip | 1153 MB | ✓ complete, valid |
| Pronouns_2of2.zip | 903 MB | ✓ complete, valid |
| Seasons_1of1.zip | 1194 MB | ✓ complete, valid |
| Colours_1of2.zip | 67 MB | ✗ partial (gave up after 10 retries) |

### What the dictionary contains (22 real entries)
- Animals: animal, horse, mouse (3)
- Days_and_Time: second, morning, afternoon, evening, night, time (6)
- Greetings: good evening, good night, thank you, pleased (4)
- Pronouns: we, you (plural), they (3)
- Seasons: summer, spring, winter, fall, season, monsoon (6)

### Why only 3-6 per category
INCLUDE's zips are split mid-category. `Animals_2of2.zip` doesn't have "all the animals after the halfway point" — it has just 3 animals because the authors chose an arbitrary partition. Same for every split zip. Each category's "first half" likely contains the rest. Animals_1of2 (~1.7GB) probably has 20+ more animals, but we didn't download it.

### What we didn't download
- Animals_1of2 (~1.7GB)
- Greetings_1of2 (~1.5GB)
- Colours_1of2 (~1.2GB — failed 10 retries)
- Pronouns_1of2 (~1.4GB)
- Days_and_Time_1of3 + 2of3 (each ~1.0-1.2GB)

These would bring the dictionary to maybe 100-150 entries. Not pursued due to bandwidth constraints (each takes 1-2 hours and frequently drops).

### Connection issues
- Many files reach 90%+ then drop (`curl: (18) transfer closed with N bytes remaining to read`)
- Zenodo rate-limited at ~133 requests / 5 minutes
- Zenodo's `api/records/4010759` returns 504 Gateway Timeout intermittently

## 7. Outstanding Issues / Future Work

### High priority
1. **Fingerspelling clips are placeholders** — pastel cards with the letter, not real ISL alphabet footage. Replacing with real ISL alphabet is the highest-value follow-up. The `Hemg/Indian_sign_language_dataset` HuggingFace dataset (35 alphabet classes, 292MB) is a candidate.
2. **Dictionary is sparse** — 22 entries means most story words fall back to fingerspelling. Adding the remaining INCLUDE halves (Animals_1of2, Greetings_1of2, Colours_1of2, Pronouns_1of2, Days_and_Time_1of3 + 2of3) would push it to ~100-150. Plus 263 total INCLUDE classes means most storybook words still won't be covered.

### Medium priority
3. **Safari onboundary granularity** — fires only at sentence boundaries, not word. Frontend README documents this. Fallback would be pre-computed timestamps from `utterance.rate`.
4. **Clip quality** — "first file wins" picks a random signer. A quality pass would inspect frames for open eyes, sign in frame, no blur.
5. **Marker file race** — `extract()` marker should only be written after success AND size-match. Currently can mark partial extracts as done.
6. **Lru_cache invalidation** — `get_sign_dict()` doesn't pick up changes after first call. Restart backend to refresh, or add a file-watch invalidator.

### Low priority / never
- The `pipe` ternary cleanup in `main.py:149-150` — cosmetic
- The `/translate` endpoint — googletrans dropped, would need a real translation service
- ISL→text webcam pipeline — explicitly out of scope
